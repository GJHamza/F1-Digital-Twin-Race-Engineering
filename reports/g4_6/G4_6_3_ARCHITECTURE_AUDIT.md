# G.4.6.3 — STRATEGY COMPARISON / TRADE-OFF ANALYSIS ARCHITECTURE AUDIT

## 1. Executive Overview & Objectives

Phase **G.4.6.3 Strategy Comparison / Trade-off Analysis** provides an interactive presentation UI for side-by-side evaluation of a small set of strategies (up to 4) generated by **G.4.5.5** (`StrategyOptimizer`) and formatted by **G.4.6.1** (`StrategyDashboardAdapter`).

The primary purpose is to visualize engineering trade-offs (e.g., race time vs. fuel remaining, race time vs. tire wear, pit-stop strategies, stint structures, and lap-by-lap trajectories) without modifying ranking criteria or attempting to re-evaluate optimal choices.

---

## 2. Upstream Data Availability Audit

### Available Data Contracts (via `StrategyDashboardAdapter`)

| Contract / Method | Source Object | Exposed Fields / Capabilities |
| :--- | :--- | :--- |
| `comparison_dataframe(scenario_ids)` | `RankingResult` / `RankedStrategy` | `rank`, `scenario_id`, `canonical_key`, `total_race_time_sec`, `delta_to_leader_sec`, `pit_stop_count`, `final_fuel_kg`, `avg_final_tire_wear_pct`, `warning_count`. |
| `stint_dataframe(scenario_id)` | `SimulationResult.stint_summary` or `Scenario.stints` | `stint_number`, `compound`, `start_lap`, `end_lap`, `stint_laps`, `starting_fuel`, `ending_fuel`, `fuel_consumed`, `starting_wear`, `ending_wear`, `avg_wear`. |
| `lap_dataframe(scenario_id)` | `SimulationResult.lap_records` | `lap_number`, `stint_number`, `compound`, `tire_age_laps`, `fuel_kg`, `fuel_consumed_kg`, `tire_wear_fl`, `tire_wear_fr`, `tire_wear_rl`, `tire_wear_rr`, `avg_tire_wear`, `lap_time_sec`, `pit_loss_sec`, `cum_time_sec`. |
| `validation_dataframe(scenario_id)` | `ValidationResult` | `scenario_id`, `valid`, `severity`, `violation_count`, `warning_count`, `warnings`. |

### Explicitly Unavailable Telemetry (DO NOT FABRICATE)
- **Tire Temperatures** (FL/FR/RL/RR surface or carcass temps): Not modeled in G.4.5 strategy domain.
- **Dynamic Weather / Track Degradation**: Strategy domain operates under fixed track/weather assumptions per scenario.
- **Live Safety Car / VSC Telemetry**: Not present in deterministic race pace simulator outputs.

---

## 3. Strict Ranking & Governance Rules

1. **Authoritative Source of Truth**: **G.4.5.5** (`RankingResult`) is the ONLY authority for strategy ranking.
2. **Zero Re-ranking**: The comparison layer must NEVER re-order strategies, calculate a custom composite score, or declare a alternative "winner".
3. **Leader Preservation**: `ranking_result.leader_scenario_id` is immutable. If the user excludes the leader from the comparison set, the UI displays a clear notice (*"Authoritative leader not selected"*) and does NOT assign a new leader.
4. **Presentation-Only Formatting**: Decimal precision formatting (3 decimals for race time & delta, 2 decimals for fuel & tire wear) is applied for display only.

---

## 4. Comparison Scope & Selection Mechanism

- **Maximum Comparison Set**: Hard-capped at **4 strategies max** (default: Leader + up to 3 selected strategies).
- **Session State Storage**: Selection is stored in `st.session_state["comparison_scenario_ids"]` and `st.session_state["selected_scenario_id"]`.
- **Zero Re-simulation / Re-optimization**: Modifying selection triggers Streamlit UI re-render only; no domain simulation, constraint validation, or optimization logic is executed.

---

## 5. Visualizations & Trade-Off Charts

1. **Race Time vs. Final Fuel**: Scatter/bar plot showing fuel remaining against race duration.
2. **Race Time vs. Average Tire Wear**: Scatter/bar plot showing average tire degradation against race duration.
3. **Race Time vs. Pit Stops**: Grouped comparison of pit stop counts vs total race duration.
4. **Stint / Compound Breakdown**: Horizontal timeline/bar visual showing stint lap ranges and tire compounds.
5. **Fuel Trajectory**: Lap-by-lap fuel depletion curves (`lap_number` vs `fuel_kg`) for selected strategies (when lap telemetry is available).
6. **Tire Wear Trajectory**: Lap-by-lap tire degradation curves (`lap_number` vs `avg_tire_wear` / 4-corner wear) for selected strategies.

---

## 6. Data Safety & Performance Constraints

- **Immutability**: All upstream objects (`RankingResult`, `RankedStrategy`, `SimulationResult`, `ValidationResult`) remain strictly read-only. Tested via `assert original == deep_copy`.
- **Bounded Materialization**: Telemetry (`lap_dataframe`, `stint_dataframe`) is requested ONLY for the selected comparison set (≤ 4 strategies), keeping memory footprint O(K_selected) rather than O(N_total).

---

## 7. Scope Boundaries & Non-Goals

- **DO NOT** add ML models, LLM prompts, databases, or REST APIs.
- **DO NOT** create alternative optimization objectives or trade-off weights.

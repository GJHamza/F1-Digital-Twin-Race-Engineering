// The Core Idea

A Formula 1 Car Is an IoT Device at 340 km/h

Pit Wall Command Center

Modern F1 cars carry hundreds of sensors streaming live data — engine temperature, tyre wear, aerodynamic loads — back to engineers on the pit wall and in the factory. Split-second strategy calls depend on this data.

This project simulates that exact feedback loop: a 3D physics simulation as the "physical car", a Kafka-MongoDB pipeline as the "telemetry link", and a Streamlit dashboard as the pit wall cockpit.

// System Architecture

Three Pillars of the Ecosystem

// 01 Physical Entity
3D Simulation

A WebGL environment where the user selects a vehicle and runs it on a rolling road dynamo. The physics engine computes speed, G-force, torque, aerodynamic drag, downforce, tyre temperatures, tyre wear, and GPS position — all streamed live.

Three.jsWebGLPhysics Engine
// 02 The Connection
Real-Time Pipeline

Every second, telemetry is packaged as JSON, sent via Flask to an Apache Kafka broker, then consumed by a Python engine that commits each document to MongoDB Atlas — fault-tolerant and high-throughput by design.

Apache KafkaFlaskDockerMongoDB
// 03 Digital Twin
Engineering Dashboard

A Streamlit dashboard surfaces live data — tyre status wireframes, performance radar charts, GPS lap trace, and interactive setup tuning that pushes configuration back to the car, closing the digital twin feedback loop.

StreamlitPlotlyRadar Chart
// The Telemetry Bridge

High-Throughput Messaging at Race Pace

Apache Kafka was designed for exactly this: high-throughput, fault-tolerant messaging between a physical source and a digital consumer. Each payload flows through the f1_telemetry topic to the Python data engine, then to MongoDB Atlas.
